# 유희왕 덱 사진 → 카드 목록 (ygoSolver)

덱 사진(JPG/PNG/WebP) 또는 카메라 촬영 사진에서 카드를 인식하고, 카드마다 눈으로 확인·수정한 뒤
카드명·레어도·수량(선택하면 한국어/일본어/영어 이름·공식 CID도)이 덱 순서로 담긴 Excel(XLSX)과 CSV(UTF-8 BOM)로 내려받는 로컬 웹앱입니다.
가격 정보는 아직 없습니다.

## 현재 기능 (2026-10-08)

| 기능 | 동작 |
| --- | --- |
| 카드 인식 | 실물 카드 사진·덱 편집기 스크린샷·카메라 입력, 여러 사진과 회전된 카드 처리. DRAW2 모델과 공식 일러스트 비교 사용 |
| 카드 확인·수정 | 한국어·일본어 이름으로 후보 표시, 후보 선택·수량·표시 이름 수정, 삭제와 영어 정식 이름으로 직접 추가 |
| 공식 이름 조회 | 한국어·일본어·영어 이름과 CID 조회. 확인된 Reactor·Baybarron·The Fallen & The Virtuous 모델 이름 차이 처리, 조회 실패 이유 표시와 명시적 재조회 |
| 레어도 선택 | 공식 한국어·일본어 판본에 있는 레어도 중 직접 선택. 해당 카드의 가장 낮은 레어도가 기본값이며, 같은 CID·레어도끼리 수량 합산 |
| 내보내기 | XLSX와 UTF-8 BOM CSV. 기본은 카드명·레어도·수량, 한국어·일본어·영어 카드명과 CID는 각 체크박스를 켰을 때만 그 뒤에 포함. 메인 덱 몬스터 → 마법 → 함정 → 엑스트라 덱 몬스터 순(EDOPro식)으로 정렬 |
| 최종 확인 | 이름·수량·레어도를 직접 확인한 뒤 다운로드. 카드 내용이나 내보내기 옵션을 바꾸면 최종 확인 해제 |

최근 독립 작업 폴더의 전체 테스트는 **231개 실행, 230개 통과, 실패·오류 0, 건너뜀 1**입니다(2026-10-08).
건너뛴 기존 실제 사진 테스트는 이 작업 폴더에 없는 `data/references`와 `userDataset`을 필요로 합니다.
내보내기 열의 16가지 조합과 CSV/XLSX 실제 내용을 검증했으며, Streamlit AppTest로 미리보기·다운로드 일치와 최종 확인 해제를 확인했습니다.
겹친 카드 누락, 강한 반사, 학습·참조 범위 밖 카드에는 한계가 있습니다. 스크린샷의 수량 배지 읽기, 사진에서 레어도 판별, 가격 조회는 구현하지 않았습니다.
사진별 인식 결과와 검증 범위는 아래 평가 기록을 참고하세요.

## 저장소에 포함되는 것

애플리케이션·테스트·실행 설정·사용법·제삼자 라이선스 고지를 포함합니다.
모델, 공식 카드 DB와 이미지 캐시, 실험 로그, 개인 평가 사진(`userDataset/`), 생성 보고서(`outputs/`),
로컬 에이전트·인수인계 문서, `.env`와 Streamlit 비밀 설정은 Git에서 제외합니다. 로컬 파일은 삭제하지 않습니다.
아래에 언급되는 과거 평가 사진·보고서·스냅숏 수치는 개발 환경의 기록이며 해당 파일은 공개 저장소에 포함되지 않습니다.

새로 복제한 환경에서는 모델을 내려받고 **공식 카드 목록과 레어도 DB를 준비해야 내보낼 수 있습니다.**
모델을 받은 다음, 처음 DB를 만들 때는 수집 날짜를 스냅숏 이름으로 사용합니다:

```powershell
$snapshotDate = Get-Date -Format yyyy-MM-dd
.venv\Scripts\python -X utf8 inventory.py --snapshot $snapshotDate --inventory-only
.venv\Scripts\python -X utf8 rarities.py --snapshot $snapshotDate
```

기존 DB 갱신·참조 라이브러리 준비 방법은 아래 해당 절을 따르세요.
실제 사진 회귀 테스트는 로컬 모델·라이브러리·평가 사진이 있어야 실행되며, 없는 환경에서는 건너뜁니다.

## 실행 (Windows, Python 3.13)

PowerShell에서 프로젝트 폴더로 이동한 뒤:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
```

또는 위 과정을 한 번에 하는 스크립트:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

브라우저에서 http://localhost:8501 이 열립니다. `.streamlit/config.toml` 설정으로 이 PC에서만 접속할 수 있고(`address = "localhost"`),
업로드는 서버에서 파일당 20MB로 제한되며(`maxUploadSize = 20`), 사용 통계 전송은 꺼져 있습니다.

테스트: `.venv\Scripts\python -X utf8 -m unittest discover -s tests`

## 첫 실행: 모델 다운로드 (약 427MB)

처음 열면 **모델 다운로드 (약 427MB)** 버튼이 나옵니다. 누르면 Hugging Face
[HichTala/draw2](https://huggingface.co/HichTala/draw2) 의 고정 리비전에서 ONNX 모델 3개
(검출 `ygo_yolo.onnx` 39MB, 분류 `vit_fp32.onnx` 386MB, 이름표 `cardnames_onnx.json` 2MB)를 받아
크기와 SHA-256을 검증한 뒤 `data/models` 에 저장합니다. 진행 상황은 화면에 표시되고, 이후 실행에서는 다시 받지 않습니다.
실패하면 실패한 파일과 URL이 화면에 표시됩니다.

## 선택: 공식 이미지 비교 (로컬 참조 라이브러리)

DRAW2가 잘라낸 카드 사진을 이 PC에 등록해 둔 **공식 카드 DB 이미지**와 특징점으로 직접 비교합니다(`references.py`).
일치하면 그 카드가 첫 번째 후보로 자동 선택되고, 후보 이름 옆에 확률 대신 "공식 이미지 일치 · 특징점 N개"가 표시됩니다.
일치하지 않은 카드는 기존 DRAW2 결과와 "확인 필요" 규칙을 그대로 따릅니다. DRAW2가 모르는 신규 카드도 라이브러리에 등록되어 있으면 찾을 수 있습니다.

라이브러리는 공식 카드 DB에서 카드의 공식 이미지를 받아 `data/references` 에 저장합니다. 일러스트는 그 카드가 발매된
모든 언어(영어·일본어·한국어) 상세 페이지에 올라온 일러스트(ciid)의 합집합입니다. 일부 다른 일러스트는 일본어·한국어 페이지에만 있습니다.
이 변경 전에 등록한 카드(현재 `data/references` 의 기존 항목 포함)는 첫 발매 언어 페이지의 일러스트만 가지고 있을 수 있으며,
**앱이 기존 항목을 자동으로 다시 받지 않습니다.** 필요하면 같은 명령으로 다시 등록하세요(라이브러리가 바뀌면 이전 인식 결과가 지워집니다):

```powershell
.venv\Scripts\python references.py --cid 4007 22704                 # 공식 DB 카드 ID(CID)
.venv\Scripts\python references.py --url "https://www.db.yugioh-card.com/yugiohdb/card_search.action?ope=2&cid=4007"
.venv\Scripts\python references.py --from-catalog                   # data/catalog/cards.json 에 있는 모든 CID
```

- 화면에 등록된 **카드 종 수와 이미지 수**가 표시됩니다. 등록한 카드만 비교하며, 전체 유희왕 카드를 포함하지 않습니다.
- 라이브러리가 있으면 "공식 이미지 비교"가 기본으로 켜집니다. 라이브러리가 없으면 "초기화되지 않았습니다"라고 표시되고 이 비교는 꺼진 채로 시작합니다.
  이때도 아래 "후보별 공식 일러스트 비교"는 기본으로 켜져 있으므로, DRAW2만 쓰려면 그것도 직접 끄세요.
  비교가 켜져 있는데 라이브러리가 없거나 손상되었으면 이유를 보여 주고 인식을 막습니다. 라이브러리 없이 인식하려면 직접 비교를 끄세요.
- 비교 모드를 바꾸거나 라이브러리가 바뀌면 이전 인식 결과와 내보내기 확인 체크가 지워집니다.
- 비교 중 오류(라이브러리 손상 등)가 나면 인식 전체가 실패로 표시되며, 비교를 건너뛰고 계속하지 않습니다.
- 일치한 카드의 이름은 라이브러리에 저장된 공식 이름을 쓰므로 영어 이름 조회를 하지 않습니다(일본어판만 있는 신규 카드 포함).

## 후보별 공식 일러스트 비교 (기본 켜짐)

위 라이브러리와 별개로, DRAW2 점수가 낮은 카드(1순위 점수 50% 미만 또는 1·2순위 점수 차 10%p 미만)는
**DRAW2 상위 3개 후보의 공식 일러스트 전부**(한·일·영 페이지의 합집합)와 같은 특징점 비교를 합니다. 참조 라이브러리가 없어도 동작합니다.

- 공식 이미지 비교가 켜져 있으면 그 비교가 먼저이며, 거기서 일치하지 않은 카드만 후보별 비교를 합니다.
- 후보는 공식 DB에서 정확한 영어 이름으로 CID를 확인한 뒤 비교합니다. 받은 일러스트는 `data/candidate_references` 에 따로 저장해
  다음부터는 접속 없이 재사용합니다. 이 저장소가 커져도 기존 인식 결과나 `data/references` 는 바뀌지 않습니다.
- 판정 기준은 공식 이미지 비교와 같습니다(특징점 12개 이상 등). 기준을 모두 넘으면 **자동 확정**("일러스트 검증됨").
  기하 검증·일치 비율·분포·다른 후보 대비 차이는 넘지만 특징점이 12개 미만이면 그 후보를 맨 앞으로 올리되 **확인 필요**로 남깁니다
  ("일러스트 근거 약함"). 근거가 없거나 동률이면 DRAW2 순서를 그대로 두고 확인 필요로 남깁니다.
- 후보 이름 옆에는 DRAW2 점수(소수 둘째 자리 %)와 특징점 수를 따로 표시하며, 두 값을 섞어 확률로 만들지 않습니다.
  카드 상세에는 실제로 가장 잘 맞은 공식 일러스트(ciid)를 보여 줍니다.
- 공식 DB 조회·일러스트 다운로드·검증이 실패하면 단계·카드·이유를 보여 주고 인식 전체를 실패로 멈춥니다(DRAW2 결과만으로 대신하지 않음).
- 끄면 이전 인식 결과가 지워지고 다음 인식부터 DRAW2(와 공식 이미지 비교)만 씁니다. 처음 비교하는 카드는 일러스트를 받느라 몇 초 걸립니다.

### 공식 카드 전체 목록과 DRAW2 미지원 카드 이미지 (`inventory.py`)

공식 카드 DB의 일본어·영어·한국어 전체 카드 목록을 모두 받아 CID별로 SQLite에 저장하고, DRAW2 분류기에 이름표가 없는 카드의
공식 일러스트(DB에 올라온 모든 ciid)를 `references.py` 형식의 별도 라이브러리로 받습니다. 기존 `data/references`(102종 · 이미지 155장)는 건드리지 않습니다.

```powershell
.venv\Scripts\python -X utf8 inventory.py --snapshot 2026-10-07                   # 목록 수집 + 매핑 + 이미지
.venv\Scripts\python -X utf8 inventory.py --snapshot 2026-10-07 --inventory-only  # 목록 수집 + 매핑만
```

- 범위: `card_search.action?ope=1&sess=1&rp=100&stype=1&keyword=` 의 `request_locale=ja/en/ko` 전체 목록(공식 사이트 기준, 발표된 미발매 카드 포함).
  2026-10-07(09:16–09:21 UTC) 수집 결과: 일본어 14,305장(144쪽), 영어 14,019장(141쪽), 한국어 13,773장(138쪽), 합집합 14,342 CID.
  쪽마다 결과 수·표시 범위·행 수·중복을 확인하고, 언어별 고유 CID 수가 사이트가 알려 준 총수와 같지 않으면 실패합니다.
  이름은 각 언어 목록에 보이는 카드 이름이며(그 언어 목록에 없으면 NULL), 상세 페이지를 카드마다 다시 조회하지 않습니다.
- 매핑: DRAW2 카드 ID(13,819종) → 그 ID를 기본 ID나 일러스트별 ID로 가진 YGOPRODeck 카드(2026-10-07 스냅숏) → `konami_id`(공식 CID).
  13,818종이 서로 다른 공식 CID 13,818개에 놓였고, 나머지 1종(Get Your Game On!, 111000561, 2007 세계대회 상품 카드)은
  세 목록 어디에도 없고 공식 이름 검색도 결과가 없어 "공식 DB 밖"으로 기록했습니다. 모든 DRAW2 카드가 자리를 찾았으므로
  나머지 CID는 미지원으로 판정합니다: **지원 13,818 · 미지원 524 · 판정 불가 0**. DRAW2 카드 하나라도 자리를 못 찾으면 나머지는 "판정 불가"가 됩니다.
  이름표는 카드 정체만 알려 주며, 어떤 일러스트가 학습에 쓰였는지는 알려 주지 않습니다.
- 이미지: 미지원 524종의 목록에 있는 모든 언어(일본어 → 영어 → 한국어 순)의 상세 페이지에서 일러스트를 모아 ciid 단위로 중복을 없앴습니다.
  524종 · 이미지 569장 저장, 실패 0, "Coming Soon" 대체 이미지 0. 실패가 하나라도 있으면 `index.json` 을 새로 쓰지 않고 실패로 끝납니다.
- 결과 파일(커밋하지 않음): `data/official_cards/official_cards.sqlite`, `manifest.json`(날짜·총수·입력 해시·DB 해시),
  `unsupported_cards.txt`, `unresolved_cards.txt`, `snapshots/<snapshot>/<locale>/page_NNN.json`;
  `data/references_missing/index.json`, `images/`, `export_report.txt`·`.json`, `checkpoints/`.
- 이어 받기: 중단되면 같은 `--snapshot` 으로 다시 실행합니다. 저장된 쪽은 결과 수·표시 범위·행 수·중복을 다시 검사하고
  (원본 HTML은 보관하지 않고 그 해시만 기록하므로 쪽 내용을 해시로 다시 검사하지는 않습니다), 저장된 이미지는 sha256을 다시 검사합니다.
- 새로 수집하기: 사이트 총수가 바뀌면 같은 스냅숏은 실패하므로 새 `--snapshot` 이름을 씁니다. 다만 `data/references_missing/checkpoints/<CID>.json`
  은 스냅숏 이름을 함께 기록하므로 이름만 바꾸면 이전 체크포인트가 맞지 않아 이미지 단계가 실패합니다.
  먼저 `checkpoints` 폴더를 다른 이름(예: `checkpoints_2026-10-07`)으로 옮겨 두고 실행하세요. 새 실행은 `data/official_cards` 의 DB·manifest·보고서와
  (성공 시) `index.json` 을 덮어쓰므로, 이전 결과를 남기려면 두 폴더를 미리 복사해 두세요. 갱신 전용 기능은 없습니다.

  저장된 모든 쪽의 행이 DB에 한 번씩 있는지, DRAW2 전체 카드 ID 기준 지원 판정, manifest의 해시·크기, 미지원 라이브러리의 범위와
  모든 이미지(해시·형식·대체 이미지 아님)를 검사합니다. `--live` 를 붙이면 언어별 첫·중간·마지막 쪽을 공식 사이트에서 새로 받아 저장본과 비교하고,
  알려진 미지원 5종(CID 22691·22704·22715·22722·22723)의 `source_url` 상세 페이지에 올라온 모든 일러스트를 새로 받아 바이트 해시를 비교합니다.
  `tests/test_inventory.py` 는 기존 Claude 작성 단위 테스트(오프라인 가짜 응답)와 Codex 작성 실패 조건 테스트(`CodexCompletionTests`)를 함께 담고 있습니다.

### 레어도 (`rarities.py`)

카드마다 **레어도** 목록에서 그 카드의 레어도를 직접 고릅니다. 사진에서 레어도를 추정하지 않으며, 가격도 추정하지 않습니다.

- 출처: 공식 카드 DB의 **한국어·일본어(OCG) 판본**에 실린 레어도의 합집합만 보여 줍니다. 영어(TCG) 페이지와 TCG 전용 레어도는 쓰지 않으므로,
  내보낼 카드명을 영어로 골라도 레어도 목록은 같습니다. 목록은 `inventory.py` 로 만든 `data/official_cards/official_cards.sqlite` 에
  아래 명령이 레어도 표를 추가해야 생깁니다(앱은 이 DB만 읽고 레어도 조회로 접속하지 않습니다):

  ```powershell
  .venv\Scripts\python -X utf8 rarities.py --snapshot 2026-10-07
  ```

- 현재 데이터(레어도 스냅숏 `2026-10-07`, 카드 목록 스냅숏 `2026-10-07`, 오류 0으로 **완료**): 한국어 상품 592개·일본어 상품 1,524개의
  공식 상품 페이지에서 인쇄 74,072건을 모았습니다. 한국어 또는 일본어 목록에 있는 14,305 CID 모두 레어도가 있고(한국어 13,773·일본어 14,305),
  목록에 있으나 인쇄가 없는 카드는 0, 공식 목록에는 토큰 카드가 없습니다. 영어 목록에만 있는 37 CID는 "판본 없음"입니다.
  기존 카드 14,342행은 그대로이며 레어도 표(`rarity_*`)만 추가됩니다. 결과와 개수는 `data/official_cards/rarity_report.txt`·`.json`,
  DB 해시는 `manifest.json`에 기록됩니다.
- 수집 방식: 카드 상세 약 28,000페이지 대신 상품 목록과 상품별 카드 목록(각 카드의 모든 레어도 포함)을 읽고, 인쇄가 없는 카드와
  무작위 표본(언어별 100장 + 트러블 써니)을 카드 상세 페이지와 대조합니다. 받은 페이지는 `data/official_cards/rarity_snapshots/<스냅숏>/`에
  파싱 결과와 HTML 해시로 저장되어 같은 스냅숏을 다시 실행하면 이어서(전부 받은 뒤에는 네트워크 없이) 진행됩니다. 저장본이 손상·불완전하면
  다시 받지 않고 실패하며, 검증 오류가 하나라도 있으면 기존 레어도 표를 바꾸지 않습니다.
  `inventory.py`로 카드 DB를 다시 만들면 레어도 표가 사라지므로 `--discard-rarity` 없이는 거부되며, 다시 만든 뒤 `rarities.py`를 새 스냅숏으로 실행해야 합니다.
- 같은 표기의 다른 마감: 공식 DB는 같은 약어를 여러 마감에 씁니다(예: 시크릿 레어 `SE`와 `SE`(SPECIAL BLUE/RED Ver.), 쿼터 센추리 시크릿 레어의
  SPECIAL Ver. 등). 앱은 공식 레어도 번호(rid)로 구분해 41종을 별도로 표시하며(`SE@43`처럼 내부 키, 화면에는 한국어 이름),
  한국어판 `P+ES`와 일본어판 `P+EXSE`처럼 언어별 약어가 다른 같은 마감은 하나로 봅니다. 일본판에만 있는 12종의 한국어 이름은 일본어 이름을 옮긴 것입니다.
- 순서와 기본값: 낮은 레어도부터 표시합니다. 노멀 → 레어 → 슈퍼 → 울트라 → 시크릿의 단계만 공식 등급 순서를 따르고,
  그 밖의 마감(패러렐·밀레니엄·홀로그래픽·얼티미트·프리즈마틱 등)의 위치는 이 앱의 정렬 규칙일 뿐 공식 순위나 시세 순서가 아닙니다. 카드를 처음 고르거나 다른 카드(CID)로 바꾸면 **그 카드의 가장 낮은 레어도**가 미리 선택됩니다
  (노멀 판이 없는 카드는 노멀이 아님). 이전 카드의 레어도는 새 카드에 있어도 이어받지 않습니다. 같은 카드에서 고른 레어도는 화면 재실행·수량/이름/언어 변경·공식 DB 다시 조회 후에도 유지됩니다.
- 이 기능 전에 열어 둔 세션의 카드는 레어도가 없으므로 처음 한 번 가장 낮은 레어도가 선택되며, 선택·수량·표시 이름은 그대로입니다.
- 공식 DB에서 한국어·일본어 판본이 없다고 확인된 카드는 오류가 아닌 "판본 없음"으로 안내하고 내보내기에서 막습니다
  (다시 조회해도 바뀌지 않으므로 다시 조회 버튼이 없음, 노멀 등으로 채우지 않음). 삭제하거나 다른 후보를 고르세요.
- 레어도 DB가 없거나 불완전·손상되었거나, 카드가 DB 스냅숏에 없으면 이유를 보여 주고 그 카드는 내보낼 수 없습니다
  (임의의 레어도로 채우지 않음). 결과는 세션 동안 저장되며 **레어도 다시 조회** 버튼으로만 다시 읽습니다.

## 사용 순서

1. **사진 올리기** — 여러 장 가능. 파일당 최대 20MB, 최대 4천만 화소. 휴대폰 사진의 EXIF 회전은 자동 보정됩니다.
2. **카드 인식** — 사진 위에 감지된 카드 번호가 표시됩니다(초록 = 인식, 빨강 = 확인 필요).
   결과 요약에 감지·자동 확정·확인 필요·공식 DB 조회 실패 장수(공식 이미지 비교를 켰다면 공식 이미지 일치 장수도)와 카드를 찾지 못한 사진이 표시됩니다.
   카드 영역은 사진을 그대로 한 번, 그리고 90°/180°/270° 돌려 세 번 더 검출합니다. 돌린 사진에서만 찾은 카드는
   이미 찾은 카드와 겹치지 않을 때(작은 쪽 면적의 30% 이하)만 추가되며, 처음 찾은 카드 영역은 바뀌지 않습니다.
3. **카드 확인·수정** — 카드마다 잘라낸 사진과 공식 참조 이미지를 비교하고, 후보 선택·표시 이름 수정·수량 수정·삭제를 합니다.
   공식 이미지 비교로 일치한 카드는 자동 선택되지만, 다른 카드와 마찬가지로 마지막 내보내기 확인은 직접 해야 합니다.
   인식 신뢰도가 낮은 카드도 1순위 후보가 미리 선택되지만 자동 확정으로 세지 않고 "확인 필요"(빨강)로 남으므로,
   그 후보가 맞는지 확인하고 필요하면 다른 후보를 고르거나 선택을 비우거나 삭제하세요.
   인식 후보는 내보낼 언어 선택과 관계없이 공식 한국어 이름으로, 한국어판이 없는 카드는 공식 일본어 이름으로 표시됩니다
   (영어 이름은 후보 이름으로 쓰지 않음). 두 이름이 모두 없으면 "한국어·일본어 공식 이름 없음 (DRAW2 ID …)"으로,
   공식 DB 조회에 실패하면 "공식 이름 조회 실패"와 실패 이유가 표시되며 **공식 DB 다시 조회** 버튼으로만 다시 시도합니다.
   빠진 카드는 영어 정식 카드명으로 **직접 추가**합니다(공식 DB 조회가 성공해야 추가됩니다).
   카드마다 **레어도**를 확인하고 필요하면 바꿉니다(위 "레어도" 참고).
4. **내보내기** — 같은 공식 CID·같은 레어도의 카드는 수량이 합산되고, 같은 카드라도 레어도가 다르면 다른 줄로 나뉩니다
   (같은 CID의 줄들은 카드명이 같아야 합니다). 화면의 "N장, M종"에서 종 수는 서로 다른 CID 수이며 줄 수는 따로 표시됩니다.
   확인이 필요한 카드(레어도 미선택·조회 실패 포함)가 남아 있거나 "모든 카드의 이름·수량·레어도를 직접 확인했습니다"를 체크하지 않으면 다운로드 버튼이 비활성화됩니다.
   체크한 뒤 사진·후보·레어도·언어·표시 이름·수량·추가 열 선택을 바꾸거나 카드를 추가·삭제하면 체크가 풀리므로 다시 확인해야 합니다.
   정렬 결과(줄 순서)가 바뀌거나 정렬 정보를 읽지 못한 경우에도 체크가 풀립니다.
   XLSX/CSV와 화면 미리보기 열은 기본으로 **카드명, 레어도, 수량** 3개이며 레어도는 한국어로 표시합니다.
   내보내기 영역의 **한국어 카드명 / 일본어 카드명 / 영어 카드명 / CID** 체크박스(기본 해제)를 각각 켜면 해당 열이
   수량 뒤에 추가되며, 몇 개를 고르든 순서는 항상 카드명, 레어도, 수량, 한국어 이름, 일본어 이름, 영어 이름, 공식 CID입니다.
   선택은 화면을 다시 그려도 유지되고 미리보기·XLSX·CSV에 똑같이 적용됩니다. CID 열을 빼도 합산은 항상 공식 CID·레어도 기준입니다.

   **줄 순서**(미리보기·XLSX·CSV 공통, 정렬 옵션 없음)는
   [EDOPro의 정렬 기준](https://github.com/edo9300/edopro/blob/c250b6ab9bebb6eca9fdd07ee0c5bd2278426e81/gframe/data_manager.cpp#L668-L725)을 참고합니다(`deck_order.py`).
   EDOPro는 메인·엑스트라·사이드 덱을 따로 정렬하지만, 이 앱은 한 목록에서 엑스트라 덱 몬스터를 맨 뒤에 배치합니다.
   - 큰 묶음: 메인 덱 몬스터 → 마법 → 함정 → 엑스트라 덱 몬스터. 엑스트라 덱은 융합·싱크로·엑시즈·링크(이들의 펜듈럼 포함)이고,
     의식 몬스터와 그 밖의 펜듈럼 몬스터는 메인 덱에 둡니다.
   - 메인 몬스터는 일반 → 효과 → 의식, 엑스트라는 융합 → 싱크로 → 엑시즈 → 링크. 같은 종류 안에서는 레벨/랭크/링크 수,
     공격력, 수비력이 높은 순, 그다음 카드 번호(passcode) 오름차순입니다.
     일부 공식 카드는 카드 번호 연결 정보가 없습니다. 이런 카드는 종류·레벨·공격력·수비력이 모두 같을 때에만
     카드 번호가 있는 카드 뒤에 오고, 그들끼리는 공식 CID 오름차순입니다.
     공격력·수비력 "?"는 0보다 뒤이고, 링크 몬스터의 수비력 "-"는 비교하지 않습니다.
   - 마법은 일반 → 의식 → 속공 → 지속 → 장착 → 필드, 함정은 일반 → 지속 → 카운터, 그다음 카드 번호 오름차순입니다(카드 번호가 없는 카드는 같은 종류 안에서 뒤, CID 오름차순).
   - 카드명·종족·속성·펜듈럼 스케일·튜너/스피릿/유니온/리버스 여부는 순서에 영향을 주지 않습니다.
     같은 카드의 레어도별 줄은 붙어 있고 낮은 레어도부터입니다(위 레어도 순서).
   - 정렬 정보는 로컬 공식 카드 DB(`official_cards.sqlite`)의 일본어 공식 목록 정보와 카드 번호에서만 읽습니다(접속 없음).
     DB가 없거나 손상되었거나, 카드가 없거나, 일본어 정보를 해석할 수 없거나, 카드 번호가 있는데 잘못된 값이면
     CID와 이유를 표시하고 미리보기·다운로드를 막습니다. 이름순 등 다른 순서로 대신 내보내지 않습니다.

내보낼 카드명 언어(한국어/일본어/영어)를 고를 수 있습니다. 선택한 언어의 공식 이름이 없으면(예: 한국 미발매)
다른 언어로 바꿔 넣지 않고 "공식 이름 없음"으로 표시하며, 내보낼 표시 이름을 직접 입력하거나 언어를 바꿔야 내보낼 수 있습니다.

**표시 이름**은 내보내는 '카드명' 열에만 쓰이며 카드 식별을 바꾸지 않습니다(공식 CID와 한/일/영 공식 이름 열을 켰다면 그 값은 그대로).
카드 자체가 잘못 인식되었다면 표시 이름을 고치지 말고 인식 후보에서 다시 고르거나, 삭제한 뒤 **정확한 영어 공식 카드명**으로 직접 추가하세요.

## 한계 — 꼭 읽어 주세요

- **수량은 사진에 보이는 카드 장수입니다.** 덱 편집기 스크린샷의 ×2/×3 배지는 읽지 않습니다(OCR 없음).
  스크린샷에서 한 장으로 보이는 카드는 수량 1로 잡히므로 반드시 직접 수정하세요.
- **레어도는 사진에서 판별하지 않습니다.** 공식 한국어·일본어 판본 목록 중에서 사용자가 고르며, 기본값은 가장 낮은 레어도입니다.
  판본(수록 상품)과 일러스트는 구분하지 않으므로 같은 카드의 다른 일러스트도 같은 CID·레어도라면 한 줄로 합쳐집니다.
- **언어는 OCR이 아니라 카드 이미지 전체의 생김새로 분류합니다.** 카드 텍스트를 읽지 않으며, 한국어·일본어판 카드에 대한 성능은 보장하지 않습니다.
- DRAW2 모델이 학습한 이후에 나온 **신규 카드는 DRAW2로 인식할 수 없습니다.** 로컬 공식 참조 이미지 라이브러리에
  등록된 카드라면 공식 이미지 비교로 찾을 수 있고, 그렇지 않으면 직접 추가로 입력하세요.
- 공식 이름 조회는 공식 카드 DB(db.yugioh-card.com)에 접속합니다. 오프라인이거나 조회에 실패한 카드는 내보낼 수 없습니다(화면에 실패 이유 표시).
  조회 결과는 `data/catalog` 에 저장되어 다음에는 접속하지 않습니다.
- **공식 이미지 비교는 등록한 카드와 공식 DB에 올라온 일러스트만 찾습니다.** 등록하지 않은 카드, 공식 DB에 올라오지 않은 일러스트,
  반사가 심해 그림이 가려진 카드는 일치하지 않고 DRAW2 결과로 남습니다. 같은 카드를 기본 일러스트만 등록하면
  다른 일러스트 카드는 찾지 못할 수 있습니다(아래 평가 참고).
- 공식 이미지 비교는 느립니다. 라이브러리를 불러오는 데 몇 초가 걸리고 카드마다 비교 시간이 더해지며, 속도는 아직 개선 중이라 확정 수치를 적지 않습니다.
- 사진은 외부로 업로드되지 않습니다. 인식은 이 컴퓨터의 CPU(onnxruntime, OpenCV)에서 실행됩니다.
  네트워크는 모델 최초 다운로드, 공식 이름 조회, 참조 라이브러리 등록(`references.py`), 후보별 공식 일러스트 다운로드,
  공식 목록·레어도 DB 준비(`inventory.py`·`rarities.py`)에만 쓰입니다. 앱은 레어도를 로컬 DB에서만 읽습니다.

## 배경: 공식 앱(Neuron)과 DRAW2

- Konami 공식 앱 "遊戯王ニューロン(Neuron)"의 카드 인식 소스·가중치·API는 공개된 것을 찾지 못했습니다.
